# 完美电竞投稿助手（浏览器插件）

精校页点「定稿」后，服务端把标题、摘要、正文、封面候选和 Word 打成一个**投稿包（zip）**发到任务的飞书话题里（精校页底部的「投稿包」按钮也能随时按最新稿子重新下载）。在开放平台的新闻编辑页上把投稿包拖进插件面板，插件自动填好：

| 页面上的位置 | 填什么 |
| --- | --- |
| 标题 | 精校页上选用的标题 |
| 摘要 | 摘要（一句话，带「（听译，可能存在出入）」） |
| 内容 | 导语段（同摘要）→ 居中配图 → Q（整段加粗）/ A 交替 |
| 大预览图 702×300 | 面板上选的那张图，插件先居中裁成 702×300 再上传；网站弹「图片裁剪」时自动点确定 |
| 小预览图 184×138 | 点「同步」；没有同步按钮时单独裁成 184×138 上传 |
| TAG、新闻类型 | 不动（新闻类型默认就是文字新闻） |

插件**不会点「提交」**，填完人工检查、补 TAG 后自己提交。

## 安装（Chrome / Edge）

1. 打开 `chrome://extensions`（Edge 是 `edge://extensions`），打开右上角「开发者模式」
2. 「加载已解压的扩展程序」→ 选这个 `browser-extension` 文件夹
3. 打开开放平台的新闻编辑页，右下角出现蓝色「投稿包」按钮

插件只在开放平台的页面上工作（认页面里的「完美世界电竞开放平台」字样，不认域名），面板只在新闻编辑页出现。需要 Chrome 111 及以上。

## 使用

1. 新建或打开一篇新闻（CSGO 新闻管理 → 新增）
2. 把投稿包 zip 拖到右下角按钮上（或点开面板后点击选择文件）
3. 面板上核对标题、摘要，在候选图里点选预览图（同一张也插到正文导语下面）；不想要图就选「不上传图片」
4. 点「填写到页面」，等日志出现 ✅
5. 补 TAG，检查，提交

页面上已经有内容时会先问是否覆盖；投稿包的游戏和当前页面（CSGO / DOTA2 / Deadlock）不一致时也会提醒。

## 投稿包格式

```
task_52_投稿.zip
├── article.json
├── 20261108_…_赛前采访.docx   （插件不用，给手工投稿时用）
└── covers/
    ├── interview_1.jpg
    ├── player_1.jpg
    └── …
```

`article.json`：

```json
{
  "format": "wmpvp-news",
  "version": 1,
  "game": "csgo",
  "title": "xelex赛前采访：……",
  "summary": "IEM北京站-2026今日继续；……（听译，可能存在出入）",
  "body": [
    {"type": "p", "text": "导语"},
    {"type": "image"},
    {"type": "q", "text": "Q：……"},
    {"type": "a", "text": "A：……"}
  ],
  "covers": [{"file": "covers/interview_1.jpg", "label": "采访画面 03:12"}],
  "cover": "covers/interview_1.jpg",
  "warnings": [],
  "source": {"task_id": "52", "built_at": "2026-11-08 20:30:00"}
}
```

- `body` 按顺序填进编辑器：`q` 整段加粗，`a`、`p` 不加粗；`image` 不带 `file` 时用面板上选的预览图，带 `file`（zip 里的路径）时上传那张图。图片所在段落居中。
- `covers` 是候选图，`cover` 是默认选中的那张（可以为 `null`）。
- `warnings` 显示在面板上（比如「摘要里的比分和实际对不上」）。
- 加字段不改版本号；改了已有字段的含义才升 `version`，插件遇到不认识的版本会拒绝。

服务端生成的代码在 `backend/pipeline/package.py` 的 `build_submission`。

## 实现要点

- 内容脚本跑在页面自己的 JS 环境里（`world: "MAIN"`），这样才能拿到 Quill 实例（`.ql-container.__quill`，取不到时用 vue-quill-editor 组件上的 `quill`）。
- 标题、摘要：用 `HTMLInputElement` 原型上的 setter 赋值再派发 `input` 事件，Vue 的 `v-model` 才会更新。
- 正文：直接 `quill.setContents(delta)`，不走粘贴，格式完全可控。图片位置先放一段占位文字，再把光标放在那里、把文件塞进网站自己的正文图片上传框（`.quill-img-uploader input[type=file]`），由网站上传到 CDN 并插入；插到别处时插件会挪回来，上传失败时占位文字留着，提示手动插入。
- 预览图：同样把文件塞进网站自己的上传框，走网站的上传接口和登录态，不直接调接口。
- zip 用浏览器自带的 `DecompressionStream` 解压（`zip.js`），没有第三方依赖。

## 待在真实页面上确认

模拟页 `test/mock.html` 上全流程跑通了（正文结构和你给的已填好页面一致），但下面这些是按 Element UI 的常规行为猜的，第一次在真实页面上用时请留意日志：

1. 正文图片上传框插图的位置是否就是光标处（不是的话插件会挪，日志里会写「插错了位置」）
2. 大预览图上传后是否弹「图片裁剪」，确定按钮的文字是否含「确定」
3. 「同步」是否把大图同步到小预览图

```bash
python -m http.server 8765 --directory browser-extension
```
