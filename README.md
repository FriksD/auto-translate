# Auto-Translate-to-News

CS2 赛后采访自动翻译的本地服务：音频 → Whisper 转写 → LLM 两段式翻译润色 → 名词规范化 → Word 初稿 → 飞书发送，人工精校出终稿。

设计文档：[docs/superpowers/specs/2026-10-29-live-interview-pipeline-design.md](docs/superpowers/specs/2026-10-29-live-interview-pipeline-design.md)；直播间监视：[docs/superpowers/specs/2026-11-08-stream-monitor-redesign.md](docs/superpowers/specs/2026-11-08-stream-monitor-redesign.md)

从直播间到交稿全自动：

1. 每个赛事一个「直播间」，填 1～2 条直播链接（B 站 / YouTube / Twitch 等；国内平台默认直连，省代理流量）。直播间开着时一直录音、转写、识别画面；还没开播就等着，开播了自动开录。
2. 采访不跟比赛绑定：赛前、赛后、图间，一个人还是几个人，只要画面和转写看起来是采访，LLM 就在滚动转写里找出每一段采访的起止，采访结束后自动截取，一段采访一个任务。
3. 截下来后再识别受访者、战队和对应的比赛（HLTV 赛程 + bo3.gg），能确认是哪场比赛才在摘要里写比分；然后走转写 → 翻译润色 → Word → 飞书。
4. 「比赛」页和飞书赛程卡片上「预约」比赛 = 给这个赛事的直播间加一段自动监视的时间（开赛前 15 分钟到开赛后 5 小时），不用一直开着。
5. 飞书群里每个直播间一张卡片、每个采访一张进度卡片，随状态自动更新；需要人处理的事回复在卡片下面。
6. 初稿发出后接着在后台生成投稿信息：推荐标题、摘要（导语）、封面候选，在在线精校页上看、改、复制；定稿时飞书里才发标题和封面，导语放在 Word 正文最前面。

也可以手动提供采访音频（上传文件或视频链接）。

## 环境要求

- Python 3.10+
- Node.js 20+（只用于构建前端）
- ffmpeg（在 PATH 中，或在设置页填写路径）
- Google Chrome（访问 HLTV 用；通过 Playwright 驱动本机 Chrome，不需要另外下载浏览器）
- streamlink（`pip install -r requirements.txt` 会装上，录直播用）
- NVIDIA GPU（推荐）。faster-whisper 使用 CTranslate2 自带的 CUDA 支持，需要 CUDA 12 的 cuBLAS 和 cuDNN 9；不可用时会自动退回 CPU。

## 首次配置（设置页）

1. **代理**：默认 `http://127.0.0.1:7897`，HLTV、视频下载、LLM 共用；飞书始终直连。
   访问 HLTV 时会弹出一个 Chrome 窗口（空闲 10 分钟自动关闭）。Cloudflare 验证一般 20 秒左右自动通过；偶尔需要人工点击时会发飞书提醒，在窗口里点一下即可。
2. **LLM**：添加自定义供应商（OpenAI 兼容或 Anthropic 兼容，填写 Base URL、API Key、模型），点「测试连接」确认可用，然后为「英文清洗」和「中文成稿」两步分别选择供应商。「直播采访定位」每 30 秒调用一次，可以单独选一个响应快的模型，不选就用英文清洗的。
3. **直播间监视**：预约的监视时段（开赛前 15 分钟到开赛后 5 小时）、未开播时的探测间隔、录音保留时长、录音分段和采访判断间隔。一般不用改。
4. **飞书**（可选，推荐发到群聊）：填写自建应用的 App ID / App Secret，选择发送到群聊（chat_id）或个人（open_id）。在飞书开发者后台：
   - 开通机器人能力和 `im:message`、`im:resource` 权限，把应用拉进目标群。
   - 卡片按钮：「事件与回调 → 回调配置」选择 **使用长连接接收回调**，添加回调 **卡片回传交互**（`card.action.trigger`）。长连接是本地服务主动连出去的，不需要公网地址。
   - 群里命令（赛程、预约、直播间、监视）：「事件与回调 → 事件配置」选择 **使用长连接接收事件**，添加事件 **接收消息 v2.0**（`im.message.receive_v1`），并开通两个权限：**获取用户在群组中@机器人的消息**（`im:message.group_at_msg:readonly`）、**读取用户发给机器人的单聊消息**（`im:message.p2p_msg:readonly`）。
   - 改完权限或回调后要发布应用新版本才生效。
   - 回到设置页保存，点「发送测试卡片」：群里出现一张示例卡片，卡片下有一条话题回复；点卡片上的按钮提示「卡片按钮已连通」就配置好了。
5. **在线精校**（可选，需要内网穿透）：手机上在飞书里精校。
   - 用 ngrok 把本地服务映射出去：`ngrok http 8000 --url https://<你的域名>`，把这个地址填到设置页「在线精校地址」。
   - 经穿透进来的请求只能打开精校页，设置、API Key、任务管理等接口一律 404；本机访问不受影响。
   - 飞书开发者后台：「安全设置 → 重定向 URL」添加 `https://<你的域名>/auth/feishu/callback`；开通权限 **获取群组信息**（`im:chat:readonly`，用来确认登录的人在群里）；发布新版本。
   - 只有设置里配置的那个群的成员能登录（发送对象是个人时只有那个人）。

## 使用

### 直播间（主流程）

1. 「直播间」页「新建」：选赛事（从 HLTV 赛程里选会自动填英文赛事名，识别受访者时用它找候选战队；HLTV 打不开就手填），填 1～2 条直播链接，「走代理」按域名自动勾选（B 站、虎牙、斗鱼、抖音不走），可以手动改。也可以在飞书里发 `监视 <链接> [赛事名]`。
2. 打开监视后全自动：
   - 未开播：每分钟探测一次，开播了自动开始录制；下播了回到等待。B 站用房间接口判断，其他平台用 streamlink。
   - 录制中：每 30 秒一段录音、转写一段；每 5 秒存一帧画面，有人说话时 3×3 拼图交给视觉模型找采访镜头（没人说话的时段不调用，省钱）。
   - 出现采访迹象（采访镜头，或转写里出现 congratulations、joined by 这类话）时，让 LLM 在转写里列出所有采访；一段采访结束（两次判断一致、或镜头切走、或下一段采访已开始）就截取（前后各留 10 秒），生成任务，从「抓取背景信息」开始处理。一场直播能截出多段采访。
   - 截下来后识别受访者、战队、采访类型（赛后 / 图间 / 赛前 / 和具体比赛无关）和对手，用 bo3.gg 确认对应的比赛；确认不了就不写比分。标题按「赛事 选手 (战队) 赛后采访」生成。
   - 录音只保留最近 6 小时（截下来的采访已经复制到任务目录）。
3. 直播间详情页可以随时介入：看每条链接的状态、正在进行的采访、采访镜头时间段、滚动转写；在转写上悬停一行「设为起点 / 设为终点」，填受访者，「试听」确认后「截取并生成任务」（直播间暂停时也能截已经录下的部分）。
4. 预约：「比赛」页或飞书赛程卡片上点「预约」，给这场比赛所属赛事的直播间加一段自动监视时间（同一赛事多场预约各自一段，重叠的时间照常只录一份）。这个赛事还没有直播间就自动新建一个，链接先从 HLTV 比赛页找官方流填上，并在飞书直播间卡片下提醒「请确认 / 换成 B 站」。取消预约只删这一段时间。预约不生成任务，任务只来自截到的采访。
5. 服务重启后，开着的直播间自动接着录。
6. 旧版的「预约比赛 → 看比分 → 录制」任务在升级后会被改成已取消。

### 在飞书群里操作

在群里 @机器人（或私聊机器人）发命令，只响应设置里配置的那个群和私聊：

- `赛程`：回复一张赛程卡片，默认今天（今天没有比赛就显示最近有比赛的一天）。卡片上可以切换日期、星级，每场比赛后面有「预约」按钮，已预约的显示对应的直播间和「取消预约」；「刷新」重新从 HLTV 读取。
- `赛程 明天` / `赛程 全部` / `赛程 2星`。
- `预约 vitality`、`赛程 PGL`：按队名或赛事名搜索未来几天的比赛，术语表里的别名也能搜（如 `预约 小蜜蜂`）。
- `预约 <HLTV 比赛链接>`：直接预约。
- `直播间`：把正在监视的直播间（再补几个最近的）各发一张新卡片到群里。
- `监视 <直播链接> [赛事名]`：给直播间加 / 换链接并开始监视。有同名赛事的直播间就加到那里，没写赛事名就加到已经有这条链接的、或最近开着的那个，都没有就新建；满两条时替换同平台的那条。这条链接之前在别的直播间里开着的，那个直播间会停掉（B 站主舞台每个赛事都用同一个房间）。
- 其他内容回复用法说明。

### 飞书卡片

启用飞书后：

- **直播间卡片**（每个直播间一张，开始监视时发出）：每条链接的状态（录制中 / 未开播 / 断流重连中）、正在进行的采访或「出现采访迹象」、最近的采访镜头、今天截到的采访（点开是任务页）、最新动态。按钮：开始 / 停止监视（停止时预约的时间段一起清掉）、打开直播间页；表单：换链接（添加或替换第几条，走代理 / 直连 / 按域名自动）。断流、采访定位的 LLM 连续失败会在卡片下回复提醒。
- **采访任务卡片**（每个截到的采访、手动新建的任务一张）：进度「采访 → 初稿 → 精校」、采访来自哪个直播间和几点、识别出的受访者 / 战队 / 采访类型 / 对手、处理进度、最近三条动态。按钮：在线精校、标记完成、从失败处重试、打开任务页（需要在运行服务的电脑上打开）。
- 卡片随状态自动更新，**更新不会提醒**。**初稿就绪会在卡片的话题里 @所有人**（群里不允许机器人 @所有人 时改为普通回复），Word 附在话题里；处理失败等需要人处理的事也回复在卡片下面。
- 飞书只允许修改 14 天内发出的卡片，过期后会重新发一张。

### 在线精校

待精校的卡片上点「在线精校」（初稿就绪的提醒里也有链接），在飞书里打开精校页，第一次用飞书账号登录：

- 顶部是采访音频（可以倍速、前后跳 5 秒）和直播画面，画面随音频进度切换，用来分辨谁在说话。
- 每段中文下面可以直接改，停手 1.5 秒或点到别处自动保存；上面灰色的是英文清洗稿，只作参考。点段落的时间从这段开始听，正在播放的段落会高亮。
- 两个人可以同时改。改的是同一段时，后保存的人会看到对方的版本，选「用我的覆盖」或「用对方的」，不会悄悄覆盖。别人改过的段落标着谁改的，页面每 8 秒同步一次。
- 改完任何一个人点「定稿」：重新生成 Word，任务标记为已完成，Word 发到卡片的话题里。定稿后还能接着改，再点「重新定稿」。
- 精校页改的就是任务页里的中文稿，两边看到的是同一份。

ngrok 免费版第一次打开时会先显示一个提示页，点「Visit Site」继续即可。

### 投稿信息（标题、摘要、封面）

初稿发到飞书之后，后台接着生成投稿信息（不耽误出初稿），大约 1～2 分钟后在在线精校页顶部的「投稿信息」里出现。**没有定稿之前不会往飞书里发标题、摘要和封面**；定稿时才发：Word（摘要作为导语放在正文最前面，不加粗）、选用的标题，以及封面候选图（第一次定稿时发，重新定稿不重发）。

- **标题**：格式「选手赛后采访：核心观点」，给 4 个候选。LLM 照设置页「投稿信息 → 标题范例」学格式和语气；在线精校定稿时选用的标题会自动加到范例最前面，越用越贴近你们的风格。
- **摘要**：照「摘要范例」的格式写一句话，如「PGL布加勒斯特大师赛-2026今日继续，就在刚刚，FURIA以2-1的比分击败MOUZ，成功晋级决赛；比赛结束后，molodoy接受了BanKs的采访，谈论了这场比赛的关键回合与自己的状态。（听译，可能存在出入）」末尾的内容概括由 LLM 从稿件里提炼，句号后面的「（听译，可能存在出入）」由程序自动补上（已有就不重复）。比分、胜负、赛段由程序从比分数据里算好交给 LLM，摘要里的比分和队名对不上会提示核对。
  - 赛事中文名优先用术语表（如 `PGL Masters Bucharest` → `PGL布加勒斯特大师赛`），术语表里没有时由 LLM 翻译并提示你加进术语表。
  - 主持人在设置页「采访主持人」里按赛事配置（`PGL=BanKs`），认不出时摘要写「接受了采访」。
- **封面候选**：直播任务在采访期间每 25 秒截一张 1080p 直播画面（最多 10 张），再用镜头识别挑出采访镜头；视频任务从视频里按采访时间截帧。另外从 HLTV 下载受访选手的现场照片（选手主页的 Pictures）和战队合照。
- 在线精校页顶部的「投稿信息」里可以改标题、点选候选标题、改摘要、一键复制、看封面原图（长按保存），也可以「重新生成」。

### 手动任务

「任务」页新建任务：填 HLTV 比赛链接（推荐，阵容以比赛当时为准）或两支队伍名，选择视频链接或上传本地文件；视频较长时可以填写截取的起止时间。直播间截下来的采访也可以在「任务信息」里改为上传采访音频。

### 查看和修改结果

流水线：抓取背景信息 → 获取音频 → 语音转写 → 英文清洗 → 中文成稿 → 生成 Word → 飞书发送。任务详情页可以看和改每一步的结果：

- **中文稿**：修改后点「保存并重新生成 Word」。
- **英文清洗稿**：修改后点「保存并重新翻译」。
- **背景信息**：队名、阵容、教练就是稿件的规范写法，抓取失败或不全时在这里补；也能看到排名、近期战绩、图池和新闻。
- **名词报告**：自动替换了哪些名字，哪些需要人工核对。
- 任意阶段失败后，可以选择从该阶段重跑。

下载 Word（或在飞书卡片的话题里接收），精校后点「标记完成」（任务页或卡片上都可以）。

### 稿件格式

- `Q：` 开头的主持人问题整段加粗；`A：` 开头的选手回答不加粗。
- 全文小四（12pt），A4，字体为 Word 默认。

### 专有名词

选手名、战队名必须与 HLTV 完全一致（如 `m0NESY`、`ZywOo`），通过三层保证：

1. 阵容写入 Whisper 提示词，提高识别率。
2. LLM 两步都附带规范名表。
3. 成稿后逐级替换：拼写变体（`monesy`、`Mo Nesy`、`Zywo0`）直接归一；发音相近的（`Monessy`、`Manasi`）按发音推断；剩下的结合上下文交给 LLM 判断（如 `Shearer` → `sh1ro`）。推断出的替换在名词报告里标黄，推断不出的列入待核对。

「术语表」页可以添加别名（如 `NAVI → Natus Vincere`、`小蜜蜂 → Vitality`）和术语的固定译法。

## 数据

所有数据都在 `data/` 目录下（可用环境变量 `ATN_DATA_DIR` 修改）：

- `app.db`：任务、日志、术语表、设置
- `tasks/<id>/`：每个任务的音频、转写、各步中间稿、提示词和 Word 文件；`package.json`、`covers/`（投稿信息和封面候选）；直播间截下来的采访还有 `stills/`（采访期间截的高清画面）、`live_transcript.jsonl`（截取范围内的滚动转写）、`live.json`（来自哪个直播间、采访起止、识别结果）、`interview.wav`（截取的采访）
- `monitors/<id>/<链接>/`：直播间每条链接最近几小时的录音分段、画面、镜头识别结果和滚动转写
- `browser-profile/`：访问 HLTV 用的 Chrome 配置（保存 Cloudflare 验证状态）
